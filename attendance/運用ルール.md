# 勤怠管理（休暇調整）運用ルール台帳

運用開始: 2026-09-02　対象: 湯淺・米内（正社員）、山下・吉岡（派遣）
方針: 最初から決め切らず、実際に起きたケースごとに藤原さんが判断し、その判断を「判断ログ」に積んでルール化する。
シート: https://docs.google.com/spreadsheets/d/12qnM3b9HztgpTXWPw1PoIV51hj0qM1rsJmNxG67g6D4/edit

## 1. 現在のルール（仮 = 未検証、確定 = 実ケースで藤原さんが判断済み）

| No | ルール | 状態 | 根拠・備考 |
|---|---|---|---|
| R1 | 申請は休みたい日の1週間前まで | 仮 | 初期値。4名に周知済み（9/2 Chatwork） |
| R2 | 同じ日に休めるのは最大2名（最低出勤2名） | 仮 | 設定シート「最低出勤人数」= 2 |
| R3 | 正社員が最低1名は出勤（派遣だけの日を作らない） | 仮 | 設定シート「最低正社員出勤人数」= 1。指揮命令者不在を防ぐ |
| R4 | 急な体調不良は当日連絡し、事後に「欠」または「有」で登録 | 仮 | 4名に周知済み |
| R5 | 連休は1日1行で申請 | 仮 | シートの仕様 |
| R6 | 派遣メンバーの休みは承認と同時に派遣元へ連絡 | 仮 | 誰が連絡するか未決。9/25、山下さんの欠勤3日分（9/8・9/9・9/14）について、派遣先向け勤怠システム（締め表）への提出をもって派遣元連絡の実務は完了と藤原さんが判断（1件目）。今後同様のケースが続けば確定に昇格 |
| R7 | 同日に希望が重なった場合の優先順位 | 未決 | 候補: 先着 / 直近3か月の取得が少ない人 / 業務都合。初ケースで決める |
| R8 | 半休の扱い（同日カウントを1人分とするか0.5とするか） | 未決 | シートは安全側で1人分扱い |
| R9 | 判定OKの申請は承認してよい | 確定 | 9/4に2件連続（米内・山下、いずれも判定OK）で承認。以後、判定OKの申請は藤原さんの個別判断を待たず「承認して問題ない」として報告し、要確認の申請のみ相談する運用に切替 |
| R10 | 申請は基本、事前申請とする。当日の急な変更（体調不良など）であっても、必ず当日中に休暇申請シートの状態を更新する | 確定 | 9/18、米内さんの9/4分の事後申請（申請日が休暇日の13日後、状態欄も空欄）を受けて確定。事後・後日まとめての登録は不可 |
| R11 | 状態欄が未入力のまま残っている行は、藤原さん側から都度対応せず、本人に入力を求める | 確定 | 9/18確定。藤原さん側の工数をかけないための運用。平日朝チェックで未入力行があれば指摘し、本人対応待ちとして報告する |

## 2. 判断の流れ（現時点）

1. 本人が「休暇申請」に行を追加（状態: 申請中）
2. 平日9時のルーティンが申請中の行を検出し、仮ルールに照らした推奨判断と論点を藤原さんに報告
3. 藤原さんが承認／却下を決め、シートの状態を更新（当面は手動。API権限が入ればこちらで更新）
4. 判断の理由を下の判断ログに記録し、ルールに昇格できるものは表1を更新
