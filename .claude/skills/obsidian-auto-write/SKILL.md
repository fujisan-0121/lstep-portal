# Obsidian自動書き込みスキル

## これは何か、何のためにあるか

人は重要な決定や手順を「後で書こう」と思って、たいてい書かない。このスキルは、その"後で"をなくすためにある。
Claude(やCodex)が作業中に気づいた「これは残すべきだ」という瞬間を、ユーザーに聞かれる前に自分でMarkdownノートにして
Obsidian Vaultへ書き込む。ユーザーは「デフォルトの挙動にしてほしい」と明言しているので、遠慮せず積極的に使うこと。

ただし正直に言っておくと、このスキルは会話の文脈とdescriptionの一致度からClaude自身が判断して起動するものであり、
100%の強制ではない。より確実に「毎回必ず」動かしたい場合は、CLAUDE.md/AGENTS.mdの常時読み込み指示と組み合わせて
運用する(このリポジトリではその設定も別途行っている)。それでも見落としはゼロにはならない、という前提でユーザーには
伝えておくこと。

## 書くべきか迷ったときの判断基準

詳しい基準・NG例・良い例は `reference.md` の「書き込みトリガーの判断基準」を参照。要点だけ言うと:

- 書く: 後で自分や他人が「あれどうやったんだっけ」と聞き返しそうなこと
- 書かない: その場限りの雑談、単純作業のログ、すでにコード/コミットメッセージに残っている情報の丸写し

迷ったら「これを書かなかったら1ヶ月後に同じ調査をもう一度することになるか?」で判断する。なるなら書く。

## 実行手順

1. **Vaultパスを解決する** — `scripts/resolve-vault-path.sh` を実行する。
   - 成功(パスが標準出力に出る)→ そのパスに書き込む
   - 失敗(終了コード非0)→ 出力されるメッセージに従う。多くの場合はローカル環境でVaultパスをユーザーに一度だけ尋ね、
     `~/.config/claude-obsidian/vault-path` に保存する。クラウドセッション等でVaultに触れない場合はリポジトリ内の
     `obsidian-drafts/` へフォールバック保存し、その旨をユーザーに一言伝える(黙って書かない)。
   - 詳細な解決ロジックは `reference.md` の「Vaultパス解決」を参照。

2. **保存先フォルダとファイル名を決める** — Vault内 `03_ログ/自動記録/` 配下(ユーザーが変更していれば設定に従う)に
   `YYYY-MM-DD_短いタイトル.md` で保存する。命名・frontmatter・本文テンプレートは `reference.md` の
   「ノートフォーマット」を参照し、そこに書かれたテンプレートをそのまま使う。

3. **既存ノートとの関係を確認する** — 同じテーマの既存ノートがありそうなら、上書きではなく追記するか、
   新規ノートから `[[既存ノート名]]` でリンクする。むやみに重複ノートを増やさない。

4. **書いたら短く報告する** — 「〇〇についてObsidianに書きました: <パス>」の一行で十分。長々と内容を
   繰り返さない(ノート自体が記録なので)。

## Codex CLIとの共有について

Codex CLIはこのSKILL.md形式を読まない。同じ判断基準・書き込み手順は `reference.md` に独立した形でまとめてあり、
リポジトリ直下の `AGENTS.md` からも参照される。Claude用の詳細もCodex用の詳細も実体は `reference.md` 一本なので、
判断基準を変えるときはそこだけ直せばよい。
