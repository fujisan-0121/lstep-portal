# Obsidian自動書き込みスキル

## これは何のためにあるか

人は重要な決定や手順を「後で書こう」と思って、たいてい書かない。このスキルは、その"後で"をなくすためにある。
Claude(やCodex)が作業中に気づいた「これは残すべきだ」という瞬間を、ユーザーに聞かれる前に自分でVaultの
`03_handoffs/Session_log.md` に追記する。

**重要**: このVaultにはすでに確立された運用ルールがある(`00_START_HERE.md` / Vault直下の `AGENTS.md`)。
このスキルはそのルールを新しく作るものではなく、忠実に実行するためのものである。判断基準や書き込み手順の
詳細は必ず `reference.md` を読むこと。ここには要点しか書かない。

**絶対ルール**: このVaultにはクライアントの財務情報やM&A関連の非常にセンシティブな内容が含まれる。
`.gitignore`で除外されているM&A関連ファイルには絶対に触れない・読まない・内容を推測しない・
会話や他の場所に漏らさない。これは他のどのルールよりも優先する。

正直に言っておくと、このスキルは会話の文脈とdescriptionの一致度からClaude自身が判断して起動するものであり、
100%の強制ではない。より確実に「毎回必ず」動かしたい場合は、CLAUDE.md/AGENTS.mdの常時読み込み指示と組み合わせて
運用する(このリポジトリではその設定も別途行っている)。それでも見落としはゼロにはならない、という前提で
ユーザーには伝えておくこと。

## 書くべきか迷ったときの判断基準

詳しい基準は `reference.md` の「書き込みトリガーの判断基準」を参照。要点だけ言うと:

- 書く: 後で自分や他人が「あれどうやったんだっけ」と聞き返しそうなこと
- 書かない: その場限りの雑談、単純作業のログ、すでにコミットメッセージ等に十分残っている情報の丸写し
- 迷ったら「これを書かなかったら1ヶ月後に同じ調査をもう一度することになるか?」で判断する

## 実行手順(概要。詳細は必ずreference.mdを見ること)

1. **Vaultパスを解決する** — `scripts/resolve-vault-path.sh` を実行する。解決できなければ
   `reference.md` の「Vaultパス解決」の失敗時手順に従う(ローカルで対話できるならユーザーに一度だけ聞いて
   設定ファイルに保存)。**Vaultに直接触れないクラウド環境の場合は、リポジトリ内フォールバックではなく
   `reference.md` の「クラウドセッションでの書き込み手順」に従う** — GitHubリポジトリ
   `fujisan-0121/obsidian-codex-cowork-vault` にブランチを切って `Session_log.md` への追記をpushし、
   `main` には絶対に直接pushしない。

2. **最優先ルールを確認する** — Vaultが解決できたら、書き込む前に必ず次を確認する(存在すれば読む、
   存在しなければその旨を記録する):
   - 親プロジェクトの `AGENTS.md`(`reference.md` に記載のパス)— 最優先
   - Vault直下の `AGENTS.md` と `00_START_HERE.md` — Vaultの運用ルール本体
   - MARKELINE関連の作業なら `MARKELINE_Codex_Context/` 配下も確認(読めない場合は「読めなかった」と明記し、
     推測で断定しない)

3. **`03_handoffs/Session_log.md` に追記する** — 新しいファイルを作らず、既存の運用に合わせて
   このファイル1本に追記する。フォーマットは `reference.md` の「Session_log.mdへの追記フォーマット」に
   従う(事実・仮説・確認事項を分け、触ったファイルを明記する)。

4. **安全ルールを守る** — APIキー・パスワード・トークンは書かない。個人情報・会員情報・未公開の顧客情報は
   増やさない。AIが書いた内容は下書き(仮説)として扱う。詳細は `reference.md` 参照。

5. **書いたら短く報告する** — 「Session_log.mdに追記しました」の一行で十分。長々と内容を繰り返さない。

## Codex CLIとの共有について

Codex CLIはこのSKILL.md形式を読まない。同じ判断基準・書き込み手順は `reference.md` に独立した形で
まとめてあり、リポジトリ直下の `AGENTS.md` からも参照される。Vault自体にもすでにCodex/Cowork向けの
`AGENTS.md`があるため、このリポジトリのAGENTS.mdはそれを補完する位置づけ(lstep-portalでの作業中に
Vaultへ書き込む判断をするための入口)であり、Vault側のルールを上書きするものではない。
