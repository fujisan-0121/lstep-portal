# Obsidian自動書き込み — 詳細リファレンス

Claude Code の `obsidian-auto-write` スキルと、Codex CLI の `AGENTS.md` の両方から参照される、判断基準と
実装手順の本体。どちらのツールで動いていても、このファイルに書かれたルールに従う。

## 書き込みトリガーの判断基準

### 書く

- 仕様・設定・運用ルールの変更で、決定した理由まで含めて残す価値があるもの
  (例: 「なぜこのライブラリではなくこちらを選んだか」「なぜこの閾値にしたか」)
- セットアップ・デプロイ・障害対応など、手順を間違えるとやり直しが発生する複雑な作業をやり切った直後
- 過去のやり取りや既存ノートを見て「これ前にもやったな」と気づいたとき(2回目が起きた時点でもう書く。
  3回目を待たない)
- ユーザーが明示的に「メモして」「Obsidianに書いて」「マニュアル化して」と言ったとき(これは無条件で書く)

### 書かない

- その場限りの雑談、確認だけで終わった質問
- git のコミットメッセージやPRの説明にすでに十分残っている情報をそのまま複製するだけのもの
- 単純作業の実行ログ(「ファイルをコピーした」程度の粒度)
- まだ確定していない検討中の案(仮の議論をノートにすると後で古い情報として混乱の元になる)

### 迷ったときの一行基準

「これを書かなかったら1ヶ月後に同じ調査・同じ議論をもう一度することになるか?」
なるなら書く。ならないなら書かない。書きすぎてノイズになったVaultは、書かれていないVaultより悪い。

## Vaultパス解決

解決順序(`scripts/resolve-vault-path.sh` が実装している):

1. 環境変数 `OBSIDIAN_VAULT_PATH` が設定されていて、かつそのディレクトリが実在する → それを使う
2. 設定ファイル `~/.config/claude-obsidian/vault-path`(1行目にVaultの絶対パス)が存在し、
   その中身のディレクトリが実在する → それを使う
3. どちらも無い場合:
   - **ローカル環境で対話できる場合**: ユーザーに一度だけVaultの絶対パスを尋ね、
     `~/.config/claude-obsidian/vault-path` に保存する。以後は聞かない。
   - **対話できない/Vault自体に触れない環境の場合**(クラウドの隔離セッションなど):
     今作業しているリポジトリのルート直下 `obsidian-drafts/` にノートを保存し、
     「Vaultに直接書けなかったので `obsidian-drafts/` に下書きを置いた、ローカルで取り込んでほしい」
     と一言ユーザーに伝える。黙ってこの経路を使わない。

`resolve-vault-path.sh` は解決できたパスを標準出力に1行で返し、終了コード0で終わる。解決できなければ
終了コード1で終わり、標準エラーに次に何をすべきかのヒントを出す。

## ノートフォーマット

### 保存先フォルダ

Vault内 `03_ログ/自動記録/`(ユーザーが `~/.config/claude-obsidian/vault-path` と同じ設定ディレクトリに
`note-folder` という1行ファイルでフォルダ名を上書きしていれば、そちらを優先する)。

### ファイル名

`YYYY-MM-DD_短いタイトル.md`
例: `2026-09-01_Obsidian自動書き込みスキルの導入.md`

同じ日に同テーマの追記が発生した場合は新規ファイルを作らず、既存ファイルに追記する。

### frontmatter

```yaml
---
date: 2026-09-01
tags: [自動記録, 重要更新]  # 該当するものを選ぶ: 自動記録 / マニュアル / 重要更新 / トラブル対応
source: lstep-portal (Claude Code)  # どのプロジェクト・どのツールから書いたか
status: 確定  # 確定 / 検討中 のどちらか。検討中の内容は基本的に書かない方針だが、
              # 書く場合は必ず検討中と明記する
---
```

### 本文テンプレート

```markdown
## 背景

何が起きて、なぜこれを記録する価値があると判断したか。1〜3行で。

## 決定事項 / 内容

実際に決まったこと、やったこと。箇条書きで簡潔に。

## 手順(手順化する場合のみ)

1. ...
2. ...

## 関連

[[関連する既存ノート]] があれば書く。無ければこの節は省略してよい。
```

## Codex CLIから見たときの注意

Codex CLIはこのファイルを `AGENTS.md` 経由で読む。ツールの呼び出し方(スラッシュコマンドやSKILL.md形式)は
Claude Code特有のものだが、判断基準・Vaultパス解決・ノートフォーマットはツールに依存しないので、
そのままこのファイルの内容に従えばよい。シェルスクリプト `scripts/resolve-vault-path.sh` はどちらのツールから
実行しても同じように動く。
